## Owner request

Make the desktop interface easier to understand and operate, and improve renderer performance because the current application feels laggy.

## Usability scope

- Consolidate navigation, page headers, cards, forms, tables, tabs, status states, dialogs, and action bars into one component contract.
- Preserve the dark red-and-black Khaos Nexus identity while improving hierarchy, spacing, contrast, and readable density.
- Use progressive disclosure so advanced IDs and destructive controls are not mixed into primary workflows.
- Add clear unsaved, saving, saved, warning, and error states plus sticky Save/Cancel actions for long forms.
- Preserve keyboard navigation, visible focus, reduced motion, independent scrolling, responsive layouts, and Update Center visibility.
- Make D&D the first complete consumer of the shared UI system without changing campaign data or authorization.

## Performance scope

- Profile startup, view switching, D&D tab switching, long-list rendering, and repeated state updates before optimizing.
- Eliminate equivalent rerenders and unnecessary full-workspace DOM replacement.
- Mount heavy workspaces lazily and suspend nonessential timers/observers when their view is hidden.
- Batch DOM reads and writes, debounce search and resize work, and avoid forced synchronous layout loops.
- Render only the active D&D tab and defer non-visible heavy lists until requested.
- Cache static catalogs and normalized presentation data where safe.
- Add bounded virtualization or incremental rendering for genuinely large tables and lists.
- Keep the `v0.26.9-B` dirty-form refresh guard authoritative and do not add MutationObserver loops.

## Performance acceptance targets

- No repeated renderer long task caused by idle polling on an unchanged screen.
- View changes and D&D tab changes remain responsive without visible full-window flicker.
- Hidden modules do not continue expensive presentation refresh work.
- Typing, selecting, and scrolling remain responsive while status updates arrive.
- No regression to packaged startup phase `ready` or Limited Mode behavior.

## Validation

- Focused renderer performance and equivalent-render tests.
- UI component, navigation, accessibility, responsive, and D&D workflow tests.
- Full non-Android suite, dependency audit, syntax/package checks, Diagnostics Runtime Integration, and Windows Build.
- Packaged startup must report `phase=ready` and `limitedMode=false`.
- Manual checks at 1366×768 and 1920×1080, plus Windows scaling where available.
- Owner validation before publication.
