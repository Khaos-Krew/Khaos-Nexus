## Owner report

On 2026-08-02 at 09:18 America/Chicago, the Owner confirmed that the recovered application still flickers and reverts D&D selections before Save.

## Confirmed root cause

The D&D workspace performs a full `dnd:get` reload every 15 seconds and replaces the complete workspace DOM. The live `onDnd` listener also rerenders every incoming state payload. The emergency startup rollback intentionally restored this known baseline behavior.

## Corrective scope

- Use the existing D&D usability asset loader; do not add another main-process startup extension.
- Add a narrow renderer guard with no MutationObserver.
- Mark editable D&D controls dirty while excluding campaign navigation and immediate source toggles.
- Cache background workspace renders while dirty rather than replacing active controls.
- Clear dirty state only when a D&D mutation succeeds.
- Preserve edits when a mutation fails.
- Block campaign and tab navigation while dirty until Save or explicit discard.
- Skip equivalent background payload renders where possible.
- Preserve all stored data, IPC channels, authorization, Discord behavior, updater behavior, diagnostics, and game-adapter behavior.
