# Locked Module Center Startup Fix

Automated report #12 showed the Module Center calling its protected read IPC during startup after a stored Discord login could not be restored. That expected locked state was incorrectly surfaced as an application error.

The read handler now returns a minimal, empty locked payload containing only the access reason. It does not expose the module catalog, migration state, routes, notes, or protected settings. Owner-only mutation and export handlers remain permission-gated and unchanged.

Regression coverage verifies that locked startup no longer throws through `modules:get`.
