# Khaos Nexus v0.41.0-B — Nexus Core v1 Test Update

This build completes the first Nexus Core v1 cutover and is intended for in-app update testing.

## Nexus Core

- Adds one local Nexus Core composition root for authorization, command execution, idempotency, operational events, recovery, context isolation, worker supervision, and AI tool boundaries.
- Routes shared-scheduler save, announcement, and shutdown workflows through capability-gated, duplicate-safe Core execution.
- Routes desktop player kick/ban, hosted-server power controls, and Maintenance Mode through the same Core authority path.
- Adds append-only operational journaling, checksummed projection snapshots, and conservative interrupted-operation recovery.
- Marks crash-interrupted operations as uncertain and refuses automatic destructive replay.

## AI safety and isolation

- Formalizes separate Nexus Sentinel and Veyra context scopes.
- Nexus Sentinel cannot request campaign or D&D-session context.
- Veyra cannot request server, module, or hosted-server context.
- Adds typed Core AI tool contracts with schema validation, capability requirements, idempotency, redacted results, and fail-closed human approval support.
- AI services still do not receive raw RCON, shell, unrestricted SQL, or unrestricted Discord authority.

## Desktop and updates

- Uses one shared renderer state authority and exposes a read-only Nexus Core health projection in the desktop app.
- Adds an opt-in **Test / Beta** update channel while keeping **Stable** as the default.
- Keeps mandatory verified pre-update backups in place.
- Keeps installed and portable update verification protections in place.
- Android Companion and Mobile Gateway remain paused and excluded from this Windows production/test-update build.

## Recovery and compatibility

- Preserves existing local configuration and protected credential storage.
- Does not move desktop authority to Railway or another cloud control plane.
- Existing module compatibility paths remain only where they do not bypass Nexus Core privileged execution policy.

This is a test update candidate. Use the in-app updater and report any startup, update, module, or server-control regressions through the existing Application Monitor/diagnostics workflow.
