# Khaos Nexus v0.27.1-B — Automatic Startup Diagnostics

This unpublished beta candidate builds on `v0.27.0-B` and integrates the updateable Khaos Nexus Diagnostics runtime directly into the normal desktop startup lifecycle.

## Automatic in-app startup health check

- The normal Khaos Nexus application now runs a redacted health check after startup.
- The standalone **Khaos Nexus Diagnostics** launcher remains available through `--diagnostics`.
- Cached verified diagnostics runtimes and the embedded offline fallback remain supported.
- Local capture continues even when GitHub reporting is disabled or unavailable.
- The most recent startup result is retained locally for review.

## GitHub Application Monitor integration

- Startup health evidence uses the existing Application Monitor GitHub repository, labels, protected token, queue, retry behavior, duplicate window, batching, and daily limit.
- No second GitHub uploader or credential is introduced.
- GitHub delivery requires the Owner's existing **Automatic reporting** opt-in.
- Healthy startup evidence is sent at most once per application and diagnostics-runtime version.
- Failed, warning, or materially changed health can be reported again, while unchanged unhealthy results are throttled.
- Missing credentials or temporary network failures retain a local queued report without blocking application startup.

## Privacy and security

- Known authorization headers, bearer values, passwords, tokens, API keys, client secrets, and credential-bearing URLs receive an additional strict redaction pass before GitHub delivery.
- `secrets.bin`, Discord tokens, GitHub tokens, OAuth credentials, RCON passwords, and protected bot tokens are never copied into startup reports.
- Path-like diagnostic details are excluded from GitHub check summaries unless they are explicitly safe numeric or boolean health values.
- Report bodies and retained health evidence are bounded to prevent oversized GitHub submissions.

## Preserved behavior

- Normal application startup remains independent from diagnostics network access.
- Application Monitor remains disabled by default on new installations.
- Existing packaged-startup recovery, interface watchdogs, Limited Mode, local support bundles, and manual diagnostics remain intact.
- Android Companion and Mobile Gateway remain paused and excluded under ADR-008.

## Validation focus

Before publication:

1. Confirm the packaged application reaches startup phase `ready` with `limitedMode=false`.
2. Confirm a local startup report is created while Application Monitor is disabled and no GitHub request is made.
3. Enable Application Monitor with the existing protected GitHub token and confirm one startup report is delivered.
4. Restart the same version and confirm a healthy duplicate is not sent.
5. Confirm a changed warning or failure is queued or delivered using the existing monitor limits.
6. Inspect the GitHub body and confirm credentials and protected files are absent.

## Rollback

The current public updater release remains `v0.27.0-B`. This candidate is not published. If later published, immediate rollback will be `v0.27.0-B`.
