# Khaos Nexus v0.29.0-B — AI Homebrew Studio

This unpublished beta candidate builds on `v0.28.0-B`. It adds a copyright-safe AI Homebrew Studio to the existing D&D module while preserving `Khaos-Krew/Khaos-Nexus-AI` as the sole owner of AI providers, provider credentials, model routing, prompt policy, generation behavior, and service-side safety controls.

## Separate Khaos Nexus AI runtime

- The desktop calls the validated Khaos Nexus AI endpoint `POST /api/v1/homebrew/generations`.
- The AI service is not bundled into the Windows application.
- The desktop contains no direct OpenAI request path and stores no OpenAI provider key.
- The existing protected Khaos Nexus AI endpoint and optional service-token configuration from `v0.28.0-B` is reused.
- Loopback HTTP remains allowed only for local service endpoints; remote endpoints require HTTPS.
- Service tokens remain excluded from backups, diagnostics, public configuration, Discord bot bootstraps, renderer state, and logs.
- The cross-repository workflow pins the exact validated AI service snapshot `4036c6732061436038d1f9661a6b7e7e8768fac3` so later service changes cannot silently alter this candidate.

## AI Homebrew Studio

- Adds an Owner/local-admin-only **AI Homebrew** surface inside the existing D&D workspace.
- Supports the service’s validated content types:
  - subclass;
  - species;
  - feat;
  - spell;
  - item;
  - monster;
  - background;
  - encounter;
  - setting element.
- Supports the service’s validated target tiers: any, low, mid, high, and epic.
- Supports conservative, standard, and cinematic power-level requests.
- Accepts an original concept, title hint, system label, bounded constraints, and optional authorized inspiration records.
- Displays the exact normalized request in a preview before the Owner explicitly sends it.
- Does not generate automatically, poll in the background, or send any request without an explicit action.

## Copyright and authorization boundary

- Original concepts can be generated without attaching an inspiration source.
- Every partially entered inspiration record requires:
  - a label;
  - an allowed authorization type;
  - explicit confirmation that the user has the right to use the supplied material;
  - bounded summary or excerpt text.
- Supported authorization types are user-owned, licensed, public-domain, summary-only, and short-excerpt.
- Short excerpts and summaries are length-limited locally before any network invocation.
- Total inspiration material is capped before transmission.
- Requests to copy, reproduce, transcribe, OCR, reconstruct, clone, or closely replicate protected published classes, subclasses, spells, feats, items, monsters, stat blocks, rules, adventures, modules, chapters, sourcebooks, or related commercial material are rejected locally.
- Copyright-bypass instructions are rejected locally.
- The desktop does not provide a sourcebook upload, scan upload, OCR, or full-book reconstruction route.

## Proposal privacy and provenance

- AI output is stored only as a bounded private local proposal.
- Raw inspiration summaries and excerpts are never retained in the saved proposal.
- Raw inspiration is excluded from audit metadata, diagnostics, public configuration, Discord runtime state, bot bootstraps, and logs.
- Proposals preserve reviewable generated information including:
  - title and content type;
  - summary and design goals;
  - sections and rules text;
  - mechanics, activation, limits, and scaling;
  - balance assumptions, risks, and playtest checks;
  - provider and model metadata;
  - transformed design signals and non-raw provenance;
  - originality status and concerns.
- Audit records retain only bounded operational metadata and never store the prompt, constraints, raw inspiration, or generated private rules text.

## Existing homebrew workflow integration

- AI output does not create a normal homebrew record automatically.
- The Owner reviews the private proposal before conversion.
- A proposal marked `needs-review` cannot be converted until the originality concerns are explicitly acknowledged.
- Conversion always uses the existing D&D homebrew saver and forces the new record to begin in the normal `draft` state.
- AI-generated drafts then use the existing manual lifecycle:
  - draft;
  - submitted;
  - under review;
  - changes requested;
  - approved or rejected;
  - retired.
- Generation can never auto-submit, auto-approve, auto-enable, publish, post to Discord, or modify campaign state.
- Successful conversion is one-time: the proposal is removed from the proposal queue after the Library draft is saved, preventing accidental duplicate drafts.
- Existing manually authored homebrew remains fully usable when the AI service is unavailable.

## Service-contract alignment

- Desktop request fields match the validated service contract exactly, including `constraints` as a bounded array and `confirmedRightToUse` for inspiration authorization.
- UI aliases from earlier planning values are normalized before validation, while the visible interface presents the service’s current canonical choices.
- Empty untouched inspiration rows are omitted.
- Partially entered rows remain subject to the complete authorization and length checks.
- The live integration test verifies both the existing Co-DM campaign-turn path and the homebrew-generation path against the actual deterministic AI service.

## Stability and accessibility

- The feature uses explicit event-driven actions and introduces no permanent polling loop.
- It preserves the existing bounded D&D-root rendering and stability model.
- The packaged application continues to use the startup watchdog, full-start readiness gate, local recovery behavior, and protected persistence boundaries from earlier candidates.
- Android Companion and Mobile Gateway remain paused and excluded under ADR-008.
