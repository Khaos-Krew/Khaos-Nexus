# Khaos Nexus v0.31.0-B — Explicit AI Game Master Sessions

This unpublished beta candidate builds on `v0.30.0-B`. It adds an optional AI Game Master session mode to the existing D&D workspace while preserving `Khaos-Krew/Khaos-Nexus-AI` as the sole owner of AI providers, provider credentials, model routing, generation behavior, and service-side prompt policy.

## Separate AI runtime

- The Windows desktop uses the validated Khaos Nexus AI campaign endpoints:
  - `POST /api/v1/campaigns`
  - `GET /api/v1/campaigns/:id`
  - `POST /api/v1/campaigns/:id/turns`
- The validated AI Game Master service snapshot is pinned to `5524dcbda06c70a51774bdc843a2f9e739f7ba50`.
- The AI service is not bundled into the desktop application.
- The desktop contains no direct OpenAI request path and stores no OpenAI provider key.
- Existing protected AI endpoint and optional service-token configuration is reused.
- Loopback HTTP is allowed only for local service endpoints; remote endpoints require HTTPS.
- Service tokens remain excluded from backups, diagnostics, public configuration, renderer state, logs, and Discord bot/runtime bootstraps.

## Explicit session opt-in

- AI Game Master mode is disabled by default.
- The Owner or local administrator selects one existing planned or active desktop D&D session.
- The workspace displays the exact bounded campaign package before synchronization.
- Creating a service campaign requires explicit confirmation.
- The service campaign is created in `gm` mode and is bound privately to the selected desktop session.
- Service campaign ID, endpoint, context fingerprint, provider, model, synchronization time, and player-character names used for agency checks remain private local metadata.
- Synchronization never creates a parallel desktop campaign or session database.

## Context and stale-state control

- The synchronization preview reuses the established bounded Co-DM context builder and privacy boundary.
- The Owner explicitly controls inclusion of character details, encounter details, public session recaps, approved-homebrew summaries, and GM-authorized notes.
- Safety lines, veils, pause words, content rating, campaign tone, and permitted campaign facts are shown before synchronization.
- A stable context fingerprint is recorded with the service binding.
- The desktop can distinguish a current service copy from a stale copy when selected campaign context changes.
- Refreshing the service copy remains an explicit reviewed action.

## Turn lifecycle and retry preservation

- Each turn requires an explicit actor, table message, optional DM guidance, and final confirmation.
- Local turn input is persisted before the network request starts.
- Client turn IDs prevent duplicate local turn creation.
- Service failures retain the original actor, table message, DM guidance, retry count, and error state.
- Only failed retryable turns may be retried.
- A retry restores the retained turn to pending without deleting or duplicating its input.
- Non-retryable validation or authorization failures remain blocked.
- No background turn generation, permanent polling loop, or automatic submission is installed.

## Structured review

Every service result is revalidated in the desktop before it becomes a completed local AI Game Master turn:

- narration;
- NPC spoken dialogue;
- suggested character, ability, skill, DC, and reason;
- table choices;
- current-scene proposals;
- proposed world facts;
- proposed open-thread additions and resolutions;
- proposed notes;
- safety status and reason.

Suggested checks remain unresolved proposals. The AI does not roll dice, resolve success or failure, apply damage, change HP, alter initiative, start an encounter, grant loot, change a map, operate a game server, or schedule an action.

## Player agency

- The synchronized service instructions explicitly prohibit inventing a player character's thoughts, dialogue, consent, choice, or irreversible action.
- The desktop rejects structured dialogue attributed to a known player character.
- The desktop rejects narration that assigns protected decisions, thoughts, dialogue, consent, or irreversible actions to a known player character.
- NPC dialogue remains reviewable structured output.
- Generated narration and choices remain private until a user explicitly copies or posts them.

## Safety lock

- Service safety status `pause` or `redirect` immediately changes the local AI Game Master session to paused.
- A paused session blocks all further turn generation and retry submission.
- The workspace displays the safety reason and lock state.
- Resuming requires an explicit Owner action, confirmation, and a recorded reason or scene adjustment.
- Resume clears the lock only for the selected AI Game Master session.
- Ending AI Game Master mode clears active generation without completing or deleting the underlying desktop D&D session.

## Explicit suggestion application

- Service state updates are converted into deterministic review suggestions.
- No suggestion changes desktop campaign or session data when a turn completes.
- The Owner selects individual suggestions and chooses one existing destination:
  - the linked desktop session recap draft; or
  - campaign Co-DM notes.
- Application requires explicit confirmation and uses the existing audited D&D mutation path.
- Applied suggestion IDs, timestamps, and destinations are retained with the private turn.
- Reapplying the same selected suggestion is idempotent and does not duplicate notes.
- Mixed selections containing already-applied and unapplied suggestions are rejected until refreshed.
- Existing note length limits remain enforced.

## Recap and session ending

- Completed AI Game Master turns can produce a local recap draft for review.
- The recap includes table input, narration, and relevant safety status.
- The recap is never approved or published automatically.
- Ending AI Game Master mode is explicit and does not complete the desktop session.
- Service transcript state remains separate from the desktop's authoritative campaign and session records.

## Privacy boundary

- Raw Discord IDs, grants, channel bindings, audit records, blind rolls, protected files, map assets, service tokens, private AI proposals, and unprovided licensed full text are excluded from synchronization.
- Internal character and member record IDs are excluded.
- Private player-account names are excluded; explicitly selected campaign-role display names may appear in the reviewed campaign-role context.
- Public configuration and Discord bot/runtime bootstraps exclude AI Game Master bindings, sessions, and turns.
- Diagnostics and logs receive only bounded operational metadata rather than campaign prompts, generated narration, service tokens, or protected identifiers.
- No automatic Discord publication, voice playback, or webhook delivery is installed.

## Owner workspace

The existing D&D workspace now includes an Owner-facing AI Game Master surface with:

- service readiness and policy disclosure;
- campaign and eligible-session selection;
- exact synchronization preview;
- context-section inclusion summary;
- explicit synchronization confirmation;
- local session status and safety lock;
- explicit turn form;
- ordered turn history;
- narration, dialogue, unresolved checks, choices, and safety review;
- retry controls for eligible failures;
- selected-suggestion destination and confirmation controls;
- reasoned safety resume;
- recap-draft creation; and
- explicit AI Game Master session ending.

## Existing workflow preservation

- Manual DM workflows remain available without Khaos Nexus AI.
- Existing Co-DM, AI Homebrew Studio, AI Map Studio, campaign maps, NPC tools, encounters, quests, sessions, dice history, Discord bindings, and encounter panels remain independent.
- AI Game Master state is additive and does not replace existing campaign collections.
- Android Companion and Mobile Gateway remain paused and excluded under ADR-008.

## Cross-repository validation

The D&D AI integration workflow now runs three independent pinned jobs:

1. Co-DM and homebrew regression against AI snapshot `4036c6732061436038d1f9661a6b7e7e8768fac3`.
2. Deterministic procedural maps against AI snapshot `32021e678d90271eaf31ba5273103ecb0f562ab2`.
3. Explicit AI Game Master sessions against AI snapshot `5524dcbda06c70a51774bdc843a2f9e739f7ba50`.

The AI Game Master job verifies:

- explicit `gm`-mode campaign creation;
- bounded synchronization and protected-identifier exclusion;
- stable binding fingerprints and stale-context detection;
- local input persistence before network submission;
- retryable failure preservation and retry restoration;
- multiple service turns;
- player-agency policy and response validation;
- unresolved suggested checks;
- no desktop campaign/session mutation when generation completes;
- explicit selected-suggestion application;
- duplicate-application prevention;
- safety pause generation lock; and
- explicit reasoned resume.
