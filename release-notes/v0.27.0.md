# Khaos Nexus v0.27.0-B — UI Performance and D&D Discord Campaign Spaces

This beta builds on the startup-safe and draft-safe `v0.26.9-B` release. It improves desktop responsiveness, adds an explicit previewed workflow for creating D&D campaign spaces in Discord, and strengthens Discord message validation across D&D and server status panels.

## User-interface improvements

- Expensive hidden views no longer rebuild for every background log or status update.
- Visible renderer updates are grouped into animation frames to reduce stutter.
- Large cards and lists use browser containment to reduce unnecessary layout and paint work.
- Long renderer tasks are surfaced in diagnostics for follow-up tuning.
- Forms have clearer focus states, larger controls, responsive grids, reduced-motion support, and sticky actions for long pages.
- The existing grouped and searchable navigation shell remains intact.

## D&D Discord campaign spaces

The D&D Discord tab now separates two setup paths:

- **Use Existing Resource** keeps the current manual channel, thread, and forum-post binding workflow.
- **Create Campaign Space** previews and creates one campaign category with the selected channel template.

The default template includes:

- `campaign-info`
- `table-chat`
- `character-chat`
- `dice-rolls`
- `session-notes`
- `quests-and-loot`
- `dm-private`
- `game-table` voice

Before creation, Khaos Nexus checks the selected bot, Discord server, permissions, mapped campaign managers, proposed names, and whether each managed resource will be created, reused, or repaired. The Owner must confirm the exact preview.

## Provisioning safety

- Nothing is created automatically when a campaign is created or when the app starts.
- No Discord roles are created by default.
- Permission overwrites use mapped campaign members and keep `dm-private` restricted.
- Existing managed IDs are reused to avoid duplicate categories and channels.
- Partial failures are audited and can be retried safely.
- Unrelated Discord resources are never deleted or renamed.
- Discord API requests use bounded timeouts and rate-limit-aware retry behavior.

## Discord panel reliability

- The configured primary Nexus bot is reconciled into the D&D registered-bot selector without exposing its protected token.
- D&D campaign panels now use valid Discord action rows and are checked against Discord field, component, URL, and identifier limits before publication.
- Discord invalid-form responses now identify the rejected field without exposing campaign content or credentials.
- Server status panels now validate embeds, buttons, custom IDs, and emoji before publish or refresh.
- The status-panel text glyph that Discord rejected is blocked locally; the current `🔄` and `👥` buttons are validated before the REST request.
- Persistent panel message identity and unchanged-content skipping remain intact.

## Diagnostics and draft protection

- Electron's protected preload bridge remains frozen and is no longer overwritten by renderer instrumentation.
- Failed IPC operations remain captured and redacted at the preload boundary.
- Successful D&D mutation notifications contain only the channel name and timestamp, never payloads or results.
- Unsaved D&D edits remain protected during background refreshes and clear only after a successful mutation.
- Already-reported D&D IPC failures no longer create a duplicate unhandled-rejection record, while unrelated renderer defects remain visible.
- Expected sign-in and permission denials are excluded from retained application-error reports.

## Startup and release safety

- The startup-safe entry path remains intact.
- Packaged Windows validation must reach startup phase `ready` with `limitedMode=false`.
- Installer, portable executable, updater metadata, and checksums are validated before publication.
- Android Companion and Mobile Gateway remain paused and excluded under ADR-008.

## Beta validation focus

After loading this update, verify in a non-production Discord guild:

1. The primary Nexus bot appears in the D&D registered-bot selector.
2. Campaign-space preview and confirmed creation reuse managed resources without duplicates.
3. D&D **Refresh Panel** updates the persistent message.
4. A server status panel can be published and refreshed with its buttons intact.
5. Application Monitor does not retain new read-only `invoke`, duplicate D&D rejection, or invalid status-panel emoji fingerprints.

## Rollback

Immediate rollback is `v0.26.9-B`. Stable fallback remains `v0.26.0`.
