# Khaos Nexus v0.30.0-B — Procedural AI Map Studio

This unpublished beta candidate builds on `v0.29.0-B`. It adds original seeded procedural map proposals to the existing D&D Maps workspace while preserving `Khaos-Krew/Khaos-Nexus-AI` as the sole owner of AI providers, credentials, model routing, generation behavior, and service-side prompt policy.

## Separate AI runtime

- The Windows desktop calls the validated Khaos Nexus AI endpoint `POST /api/v1/maps/generations`.
- The validated map service snapshot is pinned to `32021e678d90271eaf31ba5273103ecb0f562ab2`.
- The AI service is not bundled into the desktop application.
- The desktop contains no direct OpenAI request path and stores no OpenAI provider key.
- Existing protected AI endpoint and optional service-token configuration is reused.
- Loopback HTTP is allowed only for local service endpoints; remote endpoints require HTTPS.
- Service tokens remain excluded from backups, diagnostics, public configuration, renderer state, logs, and Discord bot/runtime bootstraps.

## AI Map Studio

- Adds an Owner/local-admin-only AI Map Studio inside the existing D&D Maps workspace.
- Supports encounter, dungeon, settlement, region, and travel maps.
- Supports square, hex, or no grid.
- Supports sparse, standard, and dense detail levels.
- Supports parchment, blueprint, dark, and minimal themes.
- Accepts an original concept, explicit seed, dimensions, scale, biomes, desired features, and constraints.
- Displays the exact normalized request before any network invocation.
- Generation occurs only after explicit confirmation.
- The same request and seed produces the same deterministic mock structured result and service SVG.
- Existing uploaded and locally generated maps remain unchanged.

## Copyright and source boundary

- Existing map images, scans, screenshots, protected assets, and campaign map files are never sent to the AI service.
- Requests to copy, trace, redraw, OCR, reconstruct, duplicate, or closely replicate published or commercial maps are rejected locally.
- Copyright-bypass instructions are rejected locally.
- The feature does not provide a map scan upload, OCR route, or protected-map reconstruction workflow.
- Users are directed to describe terrain, routes, objectives, atmosphere, and desired original features instead.

## Structured map contract

The desktop revalidates all service output before saving or rendering it:

- title, summary, map type, seed, and grid;
- dimensions, grid type, and scale;
- unique zone and point-of-interest IDs;
- zone coordinates and dimensions within the approved grid;
- connection references to known zones;
- point-of-interest coordinates within bounds;
- encounter and hazard references to known zones;
- supported encounter difficulty labels;
- bounded exits, GM notes, and originality concerns.

A result that changes the approved map type, seed, dimensions, grid type, or scale is rejected.

## SVG safety

- Service SVG is treated as untrusted validation evidence and is never stored directly as the editable campaign map.
- Only the exact namespace `http://www.w3.org/2000/svg` is accepted.
- Only a strict inert drawing/accessibility allowlist is accepted.
- Scripts, event handlers, external links, remote images, external CSS, `url(...)`, `@import`, `foreignObject`, animation, embedded media, object/embed/iframe content, and unsupported elements or attributes are rejected.
- The desktop renders its own deterministic player-safe and GM SVG previews from the validated structured result.
- Renderer preview uses an image data URL instead of injecting service SVG markup into the document.

## Player and GM privacy

- Player-safe preview excludes secret points of interest.
- GM preview may display secret points of interest.
- GM notes are not rendered into either SVG preview.
- A label that is independently present on a public point may remain visible even if another point with the same label is secret; the secret record and location remain excluded.
- Generated proposals are private local state and are excluded from public configuration, diagnostics exports, and Discord bootstraps.
- The original raw request prompt is not retained as proposal request metadata.
- Generated result descriptions remain available inside the private proposal for review.

## Review and import

- AI output remains a private proposal until explicitly imported.
- The Owner can review:
  - player-safe and GM previews;
  - structured zones, connections, points, exits, encounters, and hazards;
  - originality status and concerns;
  - provider/model and generation metadata.
- `needs-review` originality requires explicit acknowledgement before import.
- Import creates a new protected local SVG generated from validated structured data.
- Imported maps begin inactive and GM hidden.
- Import cannot replace an existing map asset because the protected file write is create-only and atomic.
- Successful import removes the proposal from the private queue in the same state mutation, preventing duplicate imports.
- Import does not activate or reveal the map, create encounters, change fog, post to Discord, or mutate unrelated campaign state.
- Imported structured data and seed are retained in map metadata for later review and editing.
- Existing map revision history remains in use.

## Stability and accessibility

- Generation and import are explicit event-driven actions with no permanent polling loop.
- AI Map Studio observation is bounded to the D&D workspace and stabilized so it does not rerender itself repeatedly.
- The interface is responsive, supports reduced motion, and keeps large structured results scrollable.
- Existing D&D Maps, local generation, uploads, markers, protected storage, and player-safe map projection remain available without the AI service.
- Android Companion and Mobile Gateway remain paused and excluded under ADR-008.

## Cross-repository validation

The D&D AI integration workflow runs two independent pinned jobs:

1. Co-DM and homebrew regression against AI snapshot `4036c6732061436038d1f9661a6b7e7e8768fac3`.
2. Deterministic procedural maps against AI snapshot `32021e678d90271eaf31ba5273103ecb0f562ab2`.

The map job verifies:

- repeated request/seed determinism;
- structured result equality;
- service SVG equality;
- approved grid and seed preservation;
- secret-only label exclusion from player output;
- GM-note exclusion from both previews;
- inert SVG output;
- omission of raw prompt fields from proposal metadata;
- hidden and inactive import defaults;
- retention of validated structured map data.
